**Short answer:** the TOML side is `CacheConfig` in `eqproxy-config/src/schema.rs:1201` (the `[listener.<name>.cache]` table), the runtime side is `CacheSettings` in `eqproxy-net/src/cache.rs:89`, and the wiring happens at startup in `resolve_with` in `eqproxy-cli/src/main.rs`, which builds the cache and hands it to `ResolvedListener::with_cache` (`eqproxy-net/src/proxy.rs:962`).

Evidence, in order of the startup path:

1. **TOML schema.** `CacheConfig` (`eqproxy-config/src/schema.rs:1201-1222`) holds `default_ttl`, `max_memory_bytes`, `max_entry_bytes`, `disk_path`, with defaults from `impl Default for CacheConfig` at `schema.rs:1224-1233`. It is a child table of `ListenerConfig` (`schema.rs:995`, which also carries `tls`, `quic`, `max_stream_duration`, etc.). That the table is named `[listener.<name>.cache]` is confirmed by the config emitter `eqproxy-config/src/import/report.rs:166`, which writes `"[listener.{}.cache]"`. `ListenerConfig` values are parsed per-listener by `parse_listener_table` (`eqproxy-config/src/lib.rs:97`), which delegates to `parse_table` (`lib.rs:622842ab…`), and whole files go through `parse_str` (`eqproxy-config/src/lib.rs`).

2. **Runtime shape.** `CacheSettings` (`eqproxy-net/src/cache.rs:89-102`) is the resolved form: `listener`, `default_ttl`, `max_memory_bytes`, `max_entry_bytes`, `disk_dir: Option<PathBuf>`, `lock_wait`. `CacheSettings::test_defaults` is at `cache.rs:104-117` and is what tests use (`eqproxy-net/tests/e2e_cache.rs:278`).

3. **Wiring into the listener.** `ResolvedListener` (`eqproxy-net/src/proxy.rs:831`) has a `cache` field that `ResolvedListener::new` initialises to `None` (`proxy.rs:883` onward), so the cache is opt-in per listener. `with_cache(mut self, cache: Arc<crate::cache::Cache>)` at `proxy.rs:962-965` is the only production attachment point; its callers are `resolve_with` in `eqproxy-cli/src/main.rs` plus the tests `start_proxy_with` and `disk_entries_survive_a_restart` in `eqproxy-net/tests/e2e_cache.rs`. `resolve_with` is therefore the startup glue that converts the `CacheConfig` TOML values into a `CacheSettings` and wraps the result in an `Arc<Cache>`.

4. **Consumers at request time.** Inside `eqproxy-net/src/http1.rs`: the `CacheAction` enum (`http1.rs:1741-1754`), `plan_cache` (`http1.rs:f6be077b…`) and `resolve_cache_wait` (`http1.rs:1851-1887`), which calls `cache.wait` / `cache.lookup` and updates `metrics.cache_misses`. `serve_http` (`http1.rs:56f8d77a…`) is the caller of `resolve_cache_wait`. `http1.rs` imports the cache module at `http1.rs:42`.

That function is the place to read first when changing any cache knob; the schema struct and `CacheSettings` must be kept in sync, and `import/report.rs:166` must keep emitting the matching `[listener.*.cache]` keys.
