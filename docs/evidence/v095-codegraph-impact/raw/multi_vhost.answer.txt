## Direct answer

`multi_vhost` (`eqproxy-config/src/import/nginx.rs:477`) has exactly **one production caller**: the nginx `http` handler (`nginx.rs:408`). Everything else that reaches it is test code. The production blast radius is the nginx→eqproxy.toml import path only; the real cost of changing it is the large test suite in the same file that asserts on certificates, host rules and degradation rows.

## What actually breaks

- **`http` (`nginx.rs:408-467`)** — the only production call site; any signature change to `(conv, raw_listen, servers, defaults)` breaks it directly.
- **`VhostRole::Secondary` (`nginx.rs:580-588`) and the `server` helper** — they are the counterpart of `multi_vhost`'s primary/secondary split; if you change how `primary_tls`/`primary_ciphers`/`primary_listener` are derived or what the primary branch returns, these must change with it. The `None` primary early return also changes when `conv.gap(...)` is emitted, which shifts the import report.
- **The 20 tests listed above** — the observable breakage surface.
- Nothing in `eqproxy-net`, `eqproxy-core` or `eqproxy-cli` calls `multi_vhost`; per the graph its only non-test callers are inside `eqproxy-config/src/import/nginx.rs`.
