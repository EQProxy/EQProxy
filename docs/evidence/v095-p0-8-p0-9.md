## P0-8 — importer semantics

`eqproxy-config/src/import/haproxy.rs` now parses the real fetch syntax instead
of treating bare `hdr`/`hdr_dom` as a Host value:

| Source ACL | Imported condition |
|---|---|
| `hdr(host) example.com` | `headers = [{ name = "host", exact = "example.com" }]` |
| `hdr(host) -m end .example.com` | anchored header regex |
| `hdr(X-Tenant) -i acme` | `headers = [{ name = "x-tenant", regex = "(?i)^acme$" }]` |
| `hdr_dom(host) example.com` | `host = "example.com"` (engine strips `:port`) |
| `hdr_dom(host) -m end .example.com` | `host_regex = "\\.example\\.com$"` |
| `hdr_dom(host) -m beg www.` | anchored Host prefix regex |
| `hdr_dom(host) -m dom *.example.com` | domain-boundary Host regex |
| `hdr`/`hdr_dom` without `(...)` | rejected (no rule emitted) |

`hdr_dom` is accepted only for `host`; other header names are rejected instead
of inventing a domain extraction. `hdr` exact values remain byte-for-byte.
`-i`, `-m str|beg|end|sub|reg|found` and the literal escaping are handled in
the importer; invalid generated regexes are still rejected by the normal
config validation.

New tests:

- `import::haproxy::tests::hdr_and_hdr_dom_keep_distinct_semantics`
- `import::haproxy::tests::header_and_domain_acls_emit_different_configuration`
- `run_applies_imported_hdr_and_hdr_dom_with_distinct_semantics` in
  `eqproxy-cli/tests/cli_e2e.rs` (real `eqproxy` binary, real backends and
  sockets)

The E2E sends:

- `Host: literal.example` → `literal` backend through `hdr(host)`;
- `Host: literal.example:8080` → fallback, proving `hdr(host)` did not strip
  the port;
- `Host: example.com:8080` → `domain` backend through `hdr_dom(host)`;
- `Host: example.com` → `domain` backend;
- `X-Tenant: ACME` → `tenant` backend through `hdr(X-Tenant) -i`;
- missing `X-Tenant` → fallback.

Result: **1 passed, 0 failed**.

## M-01 — HTTP/1.0 chunked framing

The fix has two parts in `eqproxy-net/src/http1.rs`: the request parser rejects
HTTP/1.0 `Transfer-Encoding`, and the response path rewrites a chunked head for
an HTTP/1.0 client (dechunk, remove `Transfer-Encoding`/`Trailer`, add
`Connection: close`, downgrade the status line).

### Destructive proof: red without the fix, green restored

On 2026-11-11, both parts were temporarily disabled in the working tree: the
`te_chunked && version == 10` rejection block was removed and the response
`http10_te` gate was forced to `false`. The file was then restored with
`git checkout -- eqproxy-net/src/http1.rs`.
