# EQProxy

Language: **English**.

Minimal-observability TCP/HTTP reverse proxy, written in safe Rust
(`#![forbid(unsafe_code)]`).

## Status — v0.10.0 «the six EXT-H fixes and the gRPC bypass»

Current version: **v0.10.0** (2026-11-16), released and published on
2026-11-17: annotated, SSH-signed tag `fb56e28…` over `bdf88bb`, release run
44183459466 green, the scanned image index `sha256:f8eee767…` served
identically by GHCR and Docker Hub behind `:0.10.0` and `:latest`, 0 critical /
0 high on both architectures ([release record](docs/release-0.10.0.md)). It
closes the six `EXT-H` findings of the external audit: the PROXY header is
written before the backend TLS handshake (P0-12), gRPC runs the WASM filter and
`max_body_bytes` (P0-11), `maxconn` is scoped to the accepting listener instead
of one process-wide counter (P0-15), a compressed cache HIT cannot mix two
representations (P0-10), nginx `proxy_pass https://` keeps TLS to the backend
(P0-13) and the backend certificate is verified by its declared name (P0-14).
M-01 (HTTP/1.0 framing) is re-verified, P0-8 (`hdr`/`hdr_dom` stay distinct),
N-2 (a degraded conversion cannot be reported as converted) and P1-9 (the
import report carries no credential) are closed too. The version step is 0.10.0
rather than a 0.9.6 patch because of one major-class semver change. It follows
v0.9.5 — cache, framing and trailer fixes: AUD-01…ADV-02 and the bounded
trailers on h1, h2 and h3 — and v0.9.4, which normalized one URI and Host
before rules and forwarding, fixed HTTP/1.0 framing and closed the CONNECT,
upgrade-negotiation and proxy-credential residuals; v0.9.3 moved the published
images to `ghcr.io/eqproxy/eqproxy`. On top of v0.8.5, it is a
TCP/HTTP proxy — HTTP/1.1, HTTP/2
and HTTP/3 — with TLS termination and verified backend TLS, typed routing rules
per listener, weighted round-robin/leastconn/slow start, active health checks,
bounded queues and safe retries, hot config and certificate reload under
traffic, a bearer-gated administration plane, an opt-in server-rendered panel,
a per-listener HTTP cache, WASM plugins and the official configuration
converter (`eqproxy config import`). This file is a short pointer, not the
feature list: see [README.md](README.md) for what ships and [SPEC.md](SPEC.md)
for the specified behaviour. The audit notes at the bottom are historical
(v0.5).

Docs language: from v0.3.0, documentation is published in English only.

## Build

```bash
cargo build --release --locked
```

Binary: `target/release/eqproxy`.

## Quick start

```bash
# Validate a configuration (errors with file, line, field, cause and example)
eqproxy config validate --config eqproxy.toml

# Start the dataplane
eqproxy run --config eqproxy.toml
```

Every documented command is implemented: `config
validate/explain/diff/plan/apply/rollback/schema/import` and `doctor`.
`apply`/`rollback` manage versioned state offline, and `kill -HUP` hot-reloads
the config under traffic (S-CFG-01, fail-closed with a validated candidate
gate).

The canonical format is documented in
[docs/adr/0002-configuration-format.md](docs/adr/0002-configuration-format.md);
the full example lives in [eqproxy.toml.example](eqproxy.toml.example).

## Audit limitations (v0.5 audit; applicability policy in ADR-0030)

### cargo-geiger: incomplete `unsafe` inventory (INCONCLUSIVE)

`cargo geiger` finishes with `error: Found N warnings` because it cannot reach
some dependency files. **This is not a pass** (Veyra Proof criterion). Root
causes, all upstream of cargo-geiger (tested on 0.13.0, 0.14.0 and git main
`#118a9a28`; pinning `signal-hook-registry` to 1.4.7 fails the same way):

1. Its parser (syn) does not accept `signal-hook-registry`'s syntax
   ([cargo-geiger#240](https://github.com/geiger-rs/cargo-geiger/issues/240)).
2. It reports as "never scanned" files that rustc lists in dep-info but that
   are not scannable: markdown included with `include_str!` (clap) and
   `private.rs` files generated by build scripts and `include!`-ed
   (serde/serde_core/thiserror)
   ([#145](https://github.com/geiger-rs/cargo-geiger/issues/145),
   [#577](https://github.com/geiger-rs/cargo-geiger/issues/577)).

**Manually verified compensation** (the exact inventory gap):

| Unscanned file | `unsafe` constructions |
|---|---|
| `signal-hook-registry-1.4.8/src/lib.rs` | 30 (tokio unix signal FFI) |
| `errno-0.3.14/src/unix.rs` | 4 |
| `errno-0.3.14/src/lib.rs` | 0 |
| generated `private.rs` (serde, serde_core, thiserror) | 0 |
| clap markdown (not code) | — |

The workspace's own `unsafe` remains forbidden by `#![forbid(unsafe_code)]`;
the gap is in the signal FFI of dependencies, inventoried above.

### Miri: 22 tests not run (20 impossible + 2 too costly)

Miri **does not emulate networking or processes**
([rust-lang/miri#3449](https://github.com/rust-lang/miri/issues/3449), Miri
README): the 14 socket e2e tests and the 6 process tests are impossible under
any flag. 2 more tests (accepting an exact 1 MiB config) are excluded because
of measured cost: >8 min of interpreted parsing per test, with the boundary
covered by the regular suite and CI. Everything else runs under miri, including
4 tokio-runtime tests rewritten to use a runtime without an IO driver
(mio/kqueue is unemulated FFI on macOS,
[#4007](https://github.com/rust-lang/miri/issues/4007)).
